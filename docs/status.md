## 本批实现（最新）：录制稳定性

| 项目 | 实现 | 验证边界 |
| --- | --- | --- |
| 帧流看门狗 | 引擎每秒检查画面流：启动后 6 秒无任何帧、或录制中停流（兼容采集 5 秒/现代采集 12 秒，后者放宽因静止桌面可能合法不产出新帧），按来源故障结束会话并给出明确文案；失败时把已切段画面收尾成段并排空编码队列，尾部损失从「最多 2 个待编码段（约 3 秒）」收敛到 0。恢复/重启后有宽限窗口，暂停期间不判定。 | 看门狗、停流阈值、现代采集放宽、暂停豁免、失败排空均有单测（tests/capture/captureEngine.test.ts）。真实「无画面」场景依赖硬件故障注入，未在真机复现。 |
| 采集进程异常退出保护 | grabber 异常退出时会话内自动用原参数重启一次（QPC 时间轴连续，重启间隙由输出帧槽补齐），重启失败才进入可恢复失败；音频进程同样给一次重启机会，彻底失败只降级不终止录制；现代采集涉及权限授予，无法原地重启，保持失败路径。停止/复位会等待进行中的重启，不留孤儿进程。 | 重启成功/失败、次数用尽、现代采集不重启、停止中不动作、音频重启各路径有单测。真机进程级故障注入未复现。 |
| 采集管线重构（丢帧优化） | grabber 改为「采集线程只做 1:1 BitBlt/PrintWindow → 双编码线程做缩放与 JPEG → 单一写线程经有界队列写 stdout」。主进程卡顿不再反压到采集（pipeDrops 计数暴露）；缩放从采集线程挪走（实测 HALFTONE 缩放在采集线程 ~25ms/帧、负载下 ~39ms，是完整链路丢帧的全部来源）。表面用 DIB section（GDI 写、GDI+ 读同一块内存）：源表面屏幕 24bpp/窗口 32bpp（PW_RENDERFULLCONTENT 的 DWM 拷贝只写 32bpp DIB，24bpp 返回 True 但内容全空——实测对照确认），输出表面恒定 24bpp（GDI+ JPEG 编码原生 24bpp，32bpp 源直接编码吞吐掉一半以上）。 | 真机：1080p30 完整链路 20 秒采集缺失 **0%**（602/602，30.00fps，此前 1.17%–4.16%）；原生动态源 30fps 质量/性能两档 targetMet 均为 true；音画偏差 1–5ms；工作集峰值 862–1024MiB；窗口采集移动缩放/关闭退出通过（verify:remaining）。60fps 整屏 GDI 物理上限约 45fps（BitBlt ~22ms/帧），达标需 DXGI/WGC，另行立项。首次有效画面延迟 1.1–1.6s（受现代采集先试后回退影响），达标但受负载波动。 |

诊断增强：grabber 退出时向主进程日志输出 DONE 计数（frames/failures/poolMisses/pipeDrops），是区分「丢帧在采集端还是消费端」的唯一入口；WCS_GRABBER_ENCODERS 环境变量可强制编码线程数（1–4，诊断用）。

## 本机测量

最新（采集管线重构后）1080p30 完整链路 20 秒：采集缺失 **0%**（602/602 帧，30.00fps），首帧约 1.2–1.6 秒，音画偏差 1–5ms，1080p 导出 6–8.6 倍实时，含原生进程工作集峰值约 862–1024MiB。原生动态源对照（verify:capture-perf）：30fps 质量/性能两档 targetMet 均 true；60fps 约 45fps，未达标。报告为 dist/verify/perf-result.json 和 capture-performance.json。

历史口径（重构前）两次 60 秒完整录制：完整链路实际采集约 28.75–29.65fps，采集帧缺失约 1.17%–4.16%。当时主因是缩放占用采集线程与主进程卡顿反压，已由本批管线重构解决；60fps 与动态源完整链路验收仍待做。

第二次历史测试期间还启动了桌面点击验证工具，结果包含此系统负载。成片会重复上一帧补齐时间槽，输出帧数完整不等于每一帧都被采集；采集帧缺失率按「采集层到达帧数 vs 成片时长×目标帧率」统计，重复补帧不计入采集帧。静态桌面结果不是动态源验收。

物理摄像头探针枚举到 3 个设备，但打开设备被 Windows 拒绝权限；该项失败单独记录于 dist/verify/camera-result.json，不计作物理设备通过。

本批另用桌面自动化通道尝试真实点击，窗口截图可读，但两次前台激活均报 `failed to activate captured window`，专用探针未收到点击。未改变系统权限设置，真实点击送达仍待正常交互桌面验收。

## 仍未完成或未充分验证

- 帧流看门狗与进程自动重启的真机故障注入复验（当前覆盖为单测 + 推演）。
- 60 FPS 实时采集：GDI BitBlt 整屏物理上限约 45fps，达标需 DXGI Desktop Duplication 或 WGC 零拷贝采集后端。
- 动态源的完整链路 60fps 验收；30fps 动态源完整链路验收（当前动态源验收仅覆盖原生链路）。
- 正常交互桌面的真实点击送达、不同 DPI/多屏/提升权限窗口实测；UI Automation 控件语义识别尚未实现。
- WGC 成功路径真机验收：窗口遮挡、移动缩放、来源关闭、权限变化。现代采集仍经过 JPEG 中转，尚非 GPU 零拷贝。
- 物理摄像头多设备、拔插、驱动延迟、60 分钟同步和内存稳定性；严重编码积压仍可能降级。
- 30/60 FPS 动态源性能，以及含摄像头和原生子进程的完整长期内存目标。
- 背景聚焦虚化、独立入场预设、设备样机外框、贴图、图片/视频背景、独立源裁切。
- 用户场景预设和默认场景、iPhone/iPad 有线采集、多语言、自动更新、代码签名。
- 极端倍速（0.25× / 4×）下真实语音的听感人工复听；极端倍速会放大 WSOLA 的相位瑕疵。
- 模糊/马赛克在 4K 输出与多遮挡同帧时的性能与观感复验；两者仍保留轮廓与色彩，不等于不可恢复。

PrintWindow 对最小化、受保护内容和部分 GPU 窗口有限制。系统声音仍来自整台电脑，未实现单应用音频。M4A、3D 透视、兼容窗口采集、实时音频试听、保持音调的变速和真正的模糊/马赛克滤镜均已实现，不再列为待开发。
